00 — THE HEADLINE, CORRECTED

The biggest gain wasn't prompting. It was a bug.

Working memory says “65% → 73%, target 75%.” True — but it hides the single largest move of the two weeks. The cold-start baseline was 9/48 (19%). The jump to 31/48 (65%) — a leap of +22 tasks — did not come from any README lever.

Root cause

It came from fixing a benchmark infrastructure bug: task images shipped the wrong DuckDB dataset via a BuildKit COPY mtime-collision. The four README build-gate levers filed to attack the “27 build-errors” failure mode (h0001–h0004) were all rejected — they were chasing errors the dataset bug, not the solver, was causing.

Everything after that — every lever, every stage, both rounds — was the fight to move 31 → 36. It ended at 35/48 = 73%, a net +4 tasks of genuine lever gain.

Lesson 0 · structural

The largest, cheapest gain in the whole program was an infrastructure correctness fix found by auditing the benchmark — not by improving the solver. Audit the benchmark before you tune the model.

01.5 — THE LENS THAT EXPLAINS EVERYTHING

Two kinds of “flip”

For most of the two weeks the score read as “nothing is working” — yet real flips were happening underneath the whole time. The contradiction dissolves once you separate two things that both get called “a flipped task.”

🎲 Volatility flips (random)

A task PASSES in some trials:1 runs and FAILS in others purely because the solver sampled a different locally-plausible choice that draw. No lever involved. At trials:1 over 48 tasks, gpt-5.5 produces ~3–4 of these per run — the noise floor (CI ±4).

🎯 Lever-caused flips (not random)

A task goes FAIL→PASS because a worked example changed the committed SQL in a reproducible, artifact-attributable way. Across the whole program, exactly one flip was provably lever-caused as it happened.

They look identical at the score level and opposite at the artifact level. That is why Phase 1 read as dead: a real construct gain of +3 minus ~3 random off-construct losses = a tie. The score honestly said “README does nothing” — and that read was correct for what we could measure. The flips were only visible by reading the committed SQL, never the score.

The turn · 2026-06-13 · forensic flip-hunt

The leverable flips weren’t found by running more experiments — they were found by a deliberate forensic pass that uses the randomness itself as the search filter: ① volatility = the candidate filter (the 19-task “sensitivity set”) → ② read committed artifacts in both directions and name the exact fork → ③ classify by oracle-locality (locally-derivable vs oracle-only) → ④ pin the right branch with a precondition-gated worked example.

The honest twist: the failed stage round made the hunt possible. Round 2 netted zero flips but earned the two things the hunt depended on — it validated the delivery vehicle (a worked-example copy reaches committed SQL bleed-free at 48-task scale) and forced the artifact-judgment discipline (judge by the committed artifact, not the net score). Without that, the forensic read is impossible — you’d be fooled by the noise floor every time.

02 — THE THREE WALLS

Why README, then stages, were declared dead

These weren’t declared dead out of impatience — each is an evidence-backed wall. They interlock to define the box exactly.

🔒
Wall 1 · oracle

The deciding fact isn’t visible

Width column-sets, grain conventions, value semantics, date-range counts live only in solution__* + hidden tests. No README instruction can supply a fact the solver can’t see. Prose either went inert or re-correlated through a shared upstream filter — confirming the wrong answer.

🪞
Wall 2 · self-grading

Independence can’t be authored in-context

Any check written as solver-README prose — a new stage, a REJECT verdict, an abstention trigger — is graded by the same model in the same context that did the work. Plan-review false-rejected its own target; the abstention rail never fired (the solver self-credits the trigger). A new stage is no more independent than a new sentence.

📊
Wall 3 · variance

A real +1 hides inside the noise

At trials:1 with gpt-5.5/xhigh, run-to-run noise is ±3–4 tasks (10k bootstrap CI). A lone real win sits inside it — and the freeze-repo concurrency race forbids trials > 1, so even a genuine fix (airbnb009) couldn’t be banked on a single draw.

How they interlock

To beat the oracle wall you need an independent check → blocked by the self-grading wall. To bank small real wins instead, you need repeatability → blocked by the variance wall. Fully pinning an edit ≡ leaking the per-task answer → out of scope. The box is sealed on every side.

04 — WHY GOING BACK TO README WORKED

Same medium. Different method.

The paradox: we declared README dead, then banked every real flip via README edits. The resolution — Phase 3 changed the target class, the lever shape, and the promotion rule simultaneously.

DimensionPhases 1–2 (dead)Phase 3 (banked +4)
Target hardest failures, many oracle-only only tasks whose correct branch is locally derivable
Lever shape general prose principles copyable before→after worked-example skeletons
Composition one lever at a time, ungated precondition-gated, disjoint, composed additively (the gate IS the isolation)
Promotion single-draw net delta (buried in ±4 noise) committed-artifact + reproducibility + two-draw self-consistency

The six levers that composed into 35/48

  • 1max(points) cumulative-standings guard → f1006, f1006-hard (h0044)
  • 2feature-boundary removal guard → quickbooks002/004 held (h0045)
  • 3scoped coverage repair, gated on a fired missing-day probe → airbnb009 (h0050)
  • 4per-key inner-join-from-fact → airbnb005 (+ airbnb007) (h0053)
  • 5lap-time exclude-pit-stop-laps → f1010-medium (h0054)
  • 6build/rename preserve-all-upstream-columns → ana-eng003 (h0055)

Plus two stabilizers: h0058 keep-base-id (locks the qb002/003 over-drop coin-flip) and h0059 tmp-tier-removal inline+reconcile (banks asana003, the last bankable flipped-FAIL).

The most transferable idea · h0059

Behavior-preserving refactor + double-entry reconciliation. A refactor has a locally-computable correct answer (the before-state), so the lever can carry its own oracle-free check: before == after. That is the way past the oracle-blind wall without leaking anything.

05 — WHY IT STOPPED AT 73%

The honest ceiling

🏁

The flip program is exhausted

asana003 was the last failing task with a locally-derivable fix. Every remaining FAIL is a never-passed research-bet, oracle-blocked, or oracle-blind — it needs an exact output the solver has no local signal for.

🌫️

The noise floor masks new +1s

A longer README perturbs ~3 off-construct passers, so a real flip nets flat. h0060 responds by stabilizing the f1001 / f1003-hard coin-flips — aiming for a robust 36, not a lucky one.

📐

Past ~73% is a design question

Moving the number further is a benchmark-design change — ship a truthful schema.yml, a subset of tests/, or score against declared-not-hidden expectations — not a smarter prompt. (ana-eng004: sim 10/10, real 0/4. The sim↔real gap is unbridgeable for oracle-only-exact-schema targets.)

06 — FOR THE NEXT BENCHMARK

Eight shifts for a benchmark-agnostic workflow

Ordered by how much wasted motion they would have saved here.

Front-load a benchmark-correctness audit

The biggest gain (9→31) was a dataset-bug fix. Make “is the failure the solver’s or the harness’s?” the first question — a standard guard-script + strict audit for leaks, wrong-image bugs, lying contracts, false-green self-checks — before any lever runs.

Triage every target by oracle-locality FIRST

Before filing any prompt-side hypothesis, apply the sharp test: is the deciding fact locally derivable, or oracle-only? Only locally-derivable tasks are leverable. Phases 1–2 spent ~35 hypotheses discovering this one task at a time. The single highest-value transferable artifact.

Default the lever shape to worked-example skeletons

Confirmed across the whole program: copyable before→after skeletons reach committed code; prose principles go inert. Treat any prose-only lever as suspect-inert until proven otherwise.

Make levers precondition-gated and composable by default

Disjoint gated levers compose additively — the gate is the isolation, so you can bank many flips in one artifact and re-verify cheaply. Bake gating into the lever template.

Fix measurement before fighting it

The variance wall cost a real +1 and forced a judge-by-artifact doctrine. Fix the multi-trial blocker first (per-task/per-trial freeze repo). Until then, carry the doctrine: judge flips by committed-artifact + reproducibility, not single-draw net.

Never author independence in-context — design it as harness code

The self-grading wall is permanent for any prompt-authored check. A genuine independent verifier/abstention/judge must be operator-side harness code or a different model/context — decided at the workflow level, never a README clause. Make this a hard gatekeeper rule.

Treat benchmark-design feedback as a first-class deliverable

The honest path to 75% was a design recommendation, not a lever. Emit, per benchmark: “here is the prompt-side ceiling, and here is what the benchmark owner must change to lift it.”

Keep the reusable infrastructure — it’s already benchmark-agnostic

The spacedock first-officer loop, propose-gate gatekeeper, decision-fork simulation, smoke→full discipline, entity files with run-dir citations, and the dead-family map / WORKFLOW-REFINE ledger. One caveat: a decision-fork sim validates tendency, not real-run compliance.

07 — BOTTOM LINE

The story in three beats

First

The easy half of the climb (cold-start 19% → 65%) was really a benchmark bug fix, not clever prompting. First lesson: audit the benchmark before you tune the solver.

Second

A week proved that ordinary README instructions — and even brand-new workflow stages — cannot move the number: the answers the solver needs aren’t in what it can see (oracle wall), and any check we write is graded by the same model that did the work (self-grading wall). Declaring those dead was correct and evidence-backed.

Third

We went back to the README but changed the method: attack only tasks whose right answer is locally derivable, deliver the fix as a copy-paste worked example, gate each so they stack, and judge by whether the code actually changed — not a noisy score. That banked the four real flips to 73%. We stopped there because the rest genuinely can’t be solved without changing what the benchmark shows the solver.

For the next benchmark

Do the locality triage and the bug-audit first, default to worked-example gated levers, fix the multi-trial measurement, and ship the “what the benchmark owner must change” finding as a real deliverable.
