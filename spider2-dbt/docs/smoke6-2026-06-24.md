## What the smoke proved

1. **The wiring works end-to-end.** Views materialize leak-clean, the ade baseline
   solver runs under codex, dbt models build inside the task container, and the
   spider2-dbt verifier genuinely opens the predicted DuckDB and compares the
   `condition_tabs` table against gold via `duckdb_match`. 5/6 cells produced a real
   reward; the verifier emitted `reward.json` correctly.

2. **The zeros are real, and the dominant cause is a solver/contract mismatch, not a
   bug.** spider2-dbt grades an EXACT expected output table named in each task's
   `eval_spec` (`condition_tabs`, e.g. tpch→`client_purchase_status`,
   chinook→`dim_customer`) with specific columns. The ade `@baseline` README is tuned
   for ade-bench *repair/refactor* tasks ("do not create an answer file"; "preserve
   structure") and gives the solver no spider2-dbt output-table contract. So the solver
   builds plausibly-named models that miss the gold table name (chinook: built
   `customer`, gold wants `dim_customer`) or miss the exact column semantics (tpch:
   right table name, wrong values). The agent self-reported "0 mismatches" against its
   own interpretation — the familiar self-anchored false-green.

3. **f1001 is a packaging edge case**, not an agent failure: the build-time preflight
   that validates the source DuckDB's required source tables exited 2 (likely a
   db-name / schema mismatch — the packager guessed `--db-name f1`). Excluded from the
   solver signal; revisit the packager's db-name resolution for f1001.

## Implication for future work

The first real lever for spider2-dbt is a solver README that encodes the benchmark's
output contract: "produce a model/table named exactly as the task specifies, with the
exact columns the task enumerates." The ade README is the wrong starting point for a
flip program here — it actively discourages building new answer tables. Genuine
benchmark difficulty (spider2-dbt is a hard text-to-dbt benchmark) is a second, separate
factor; low pass rates are expected even with a tuned solver.
