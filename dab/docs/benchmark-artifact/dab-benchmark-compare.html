Spacedock (dab0022) — the model × effort grid

The crafted README needs the stronger model AND more reasoning to shine. Its best cell is gpt-5.6-sol · xhigh = 0.769 — up +0.047 from the same model at high (0.722), the largest effort gain of any spacedock cell.

On gpt-5.5 effort barely moves it (0.743 → 0.748) — but that pair mixes plugin versions (high is v0.22-era, xhigh is v0.24), so read it as version-confounded, not a clean effort test.

Even at its peak, spacedock (0.769) still trails the bare structured harness (0.779, gpt-5.6-sol·high) — the hand-written scaffolding buys reasoning-hunger and tokens, not a higher ceiling.

Benchmark. DAB scores an LLM solver on 54 analytics queries across 12 real datasets (Postgres / MongoDB / DuckDB). stratified pass@1 weights each dataset equally. Every config is a 5-run merge (270 query-trials). Solver = codex runtime; runs on razorback / harbor, uncapped.

Version caveat (spacedock only). The spacedock plugin is sourced live and materially shifts scores (~±0.04). gpt-5.5 spacedock·high is a v0.22-era run; every other spacedock cell is v0.24. So the gpt-5.5 high→xhigh spacedock slope mixes version with effort. Bare harnesses use no plugin, so they're version-immune. gpt-5.5 spacedock·xhigh substitutes one draw whose stockindex answers hit a validator crash with a clean draw (disclosed); gpt-5.5 spacedock·high has one PATENTS fresh-draw substitution.

Noise. A 5-draw mean carries ~±0.03 (direct-minimal ~±0.07) — read the whiskers, not small gaps. Reference lines: codex batch anchor 0.697, Opus-4.8 incumbent 0.654.
