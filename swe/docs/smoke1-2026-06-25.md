## Blockers hit & fixed (razorback PR #26, merged 2d8a1ae)

Three sequential blockers stopped a default `rk run` before the solver ran; all
were fixed in razorback (not worked around per-spec):

1. **Docker build:** `failed to read dockerfile: no such file or directory`. The
   materializer symlinked the `environment/` Docker build context in bind/link
   mode; BuildKit can't read a symlinked Dockerfile. → copy `environment/` as
   real files even in link mode.
2. **`max_turns`:** codex rejects any non-default `max_turns`; the upstream
   example used 400. → example spec set to 200 + actionable error message.
3. **Leakage hardening** (from codex review of the fix): copying the build context
   follows symlinks, so a disguised symlink to a denied artifact could smuggle
   answer bytes past the name-based deny filter. → resolve symlink targets and
   re-apply the deny check + source containment.

After PR #26 the default path works with **no `--materialize copy`** and **no spec
edits**. (Operational note: an interrupted run leaves a `lock.json` in its job dir;
clear the stale failed dir before retrying — the job-dir hash is keyed off the spec.)
